# LOAD-02 — Independent 100k cursor benchmark (2026-11-04)

## Contract and constraints

Task: `LOAD-02` in `docs/qa/E2E_CASES.md` / `docs/qa/e2e-agent-pack/TEST_MATRIX.md`.

- This is a **test-only branch** from `main`, not a deployment, migration or production load generator. Do not merge without independent review.
- Use a new `mkdtemp()` directory; `STORE_DB_PATH` is overridden before `new StoreService()`. Always close SQLite before teardown. No customer records, cloud URL, bank sandbox, printer or mobile device is needed.
- Seed exactly 100,000 `COMMITTED` / `UNPAID` synthetic orders with integer VND, valid timestamp and alternating STAFF creators. No revenue, payments or receipts are manufactured. Existing SQLite order triggers must produce exactly 100,000 outbox entries.
- Query the actual `StoreService.history()` method, traversing all 1000 cursor pages of size 100. Assert exact descending display code, no skipped or repeated records, STAFF only sees own orders; invalid cursors rejected. Include SQLite `EXPLAIN QUERY PLAN`.
- Emit `artifacts/perf/load02-history-100k.json` with Node/platform, row count, seed duration, traversal time, p50/p95/p99 per-page and actual plan.

## Important acceptance boundaries

This test is a deterministic **SQLite+StoreService cursor correctness benchmark** only. It is not a 100,000-order live HTTP test, cashier UI search benchmark, 100,000 PAID sales, 8 physical phones, Windows host, or store Wi-Fi performance measurement. CI p95 is informational and not a commercial LAN SLO pass. Separate field tests must measure ≥100k cashier search p95 ≤300ms and normal LAN commit p95 ≤400ms as defined in `docs/qa/ACCEPTANCE.md`.

The SQL plan and timings must be inspected. If the query shows a full scan or unacceptable tail latency, record a performance finding; do not report commercial LOAD-02 fully PASS without realistic target hardware.
