# Bank payment setup and trust model (SePay + VietQR, WIP integration)

**Code paths:** `apps/cloud-api` Nest/Fastify + PostgreSQL; `apps/store-hub/src/sync.ts`; `apps/store-hub/src/service.ts` and cashier POS. **NOT LIVE-ACCEPTED.** No merchant bank credentials or provider test events have been furnished by store owner.

## Configuration

Cloud needs `DATABASE_URL`, `CLOUD_SYNC_TOKEN` (random 32+ chars), `SEPAY_WEBHOOK_SECRET` (independent random >=32 chars), `BANK_ACCOUNT_NUMBER` and `BANK_BIN`. Use proper vault and public **HTTPS reverse proxy**; never publish credentials or open a local Hub port to the internet.

Store Hub needs `CLOUD_SYNC_URL=https://...`, identical `CLOUD_SYNC_TOKEN`, correct matching `BANK_ACCOUNT_NUMBER` and `BANK_BIN`, optional `BANK_ACCOUNT_NAME`. Do not enable MoMo or Mixed by default.

1. Merchant registers compatible receiving business account with SePay. Confirm verified bank account eligibility, fees and webhook configuration.
2. Configure **HMAC-SHA256** webhook auth in SePay, select JSON, point to `https://<cloud-host>/v1/webhooks/sepay`. The service verifies `X-SePay-Signature: sha256=...` over `<timestamp>.<raw body>` with `X-SePay-Timestamp`, ±300 seconds. Exact reference, incoming direction, expected merchant account and exact VND amount required.
3. Staff requests BANK as intent only. Cashier selects bank on POS; Hub writes a unique BMC reference and local outbox event and waits for Cloud acknowledgement before displaying VietQR. QR image is generated by VietQR image Quick Link and **not proof of payment**.
4. SePay sends signed webhook to Cloud; Cloud records unique transaction ID, including unmatched cases. Only matching unpaid order and exact amount creates settlement. Cloud verified event is pulled to Hub by authenticated TLS and durably applied once. Only then PAID and two receipt jobs appear.
5. Wrong account, direction, amount, reference, duplicate and already-paid order must remain exception for owner review. Do not manually flip PAID based on a phone screenshot.

## Validation / release gates

- SePay test-mode signed callback and real low-value transfer with exact reference. Test invalid signature, stale signed request, wrong account, wrong amount, wrong reference, duplicated bank event and order arrived after callback.
- Crash Hub while pending: outbox should replay without duplicate; cloud PG inbox UNIQUE transactions; sync cursor persist. Disconnect WAN but keep LAN cash open. Reconcile cloud verified but local already cash paid; do not double-credit order.
- Record actual source docs and provider API version in release evidence.
- VietQR standard `compact2` is useful for POC; provider recommends a merchant-owned template for official deployments. Verify generated QR account, amount and narration on 2 real banking apps.
